Projects

A few examples of the documentation systems work I enjoy most.

Trintech: AI-Assisted Documentation Workflow

Problem: The documentation team went from three writers to one while still supporting six enterprise software products, including four SaaS products, approximately 30 MadCap Flare projects, multiple Help systems, PDF outputs, and release documentation.

Work: Helped standardize Azure DevOps documentation intake across Bugs, Stories, and Features. Began using Codex to analyze tickets, identify documentation impacts, draft release notes, and suggest affected Help topics.

Why it matters: The workflow reduces repetitive analysis and gives the writer more time for accuracy, judgment, customer context, and review.

NextAxiom: Documentation Rescue & Content Reuse

Problem: Inherited a Help system with outdated, incomplete, incorrect, and missing content. Newer document types had little documentation, and shared product information was not set up for long-term maintenance.

Work: Redesigned DWEP documentation around reusable content. Built nearly 100 MadCap Flare snippets for widget properties so property information could appear directly on each widget page.

Why it matters: Customers can view relevant properties in context, while future property changes can be updated once and reused wherever they appear.

Equinix: Documentation Platform at Scale

Problem: A growing documentation organization needed to consolidate multiple product documentation sets into a single customer-facing Help system.

Work: Supported approximately 20 products, about 20 MadCap Flare projects, and a documentation team that grew to about 15 writers. Owned publishing infrastructure, GitHub repositories, staging/pre-production/production environments, localization workflows, and platform support.

Why it matters: The work became less about individual documents and more about the system behind the documentation.
